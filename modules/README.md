# Modules

**Making your own hexcrawl? Start with [BUILDING_A_MODULE.md](BUILDING_A_MODULE.md), a step-by-step procedure for the tools as they are today.**

Playable Materia Mundi modules, built from one source into a web viewer, print PDFs and a Companion manifest. The protocol is in [MODULE_FORMAT.md](MODULE_FORMAT.md). The planned Hexmarch Atlas map format (one terrain PNG per March plus a JSON) is drafted in [ATLAS_FORMAT.md](ATLAS_FORMAT.md), the Events and Procedures layer (triggers, tables and per-ruleset procedures) is drafted in [EVENTS_FORMAT.md](EVENTS_FORMAT.md), creatures, NPCs, factions and encounters (a fiction layer and a per-ruleset bestiary) are drafted in [CREATURES_FORMAT.md](CREATURES_FORMAT.md), Encounter maps (5-ft battle maps that points of interest point into, with room to grow into a VTT) are drafted in [ENCOUNTER_FORMAT.md](ENCOUNTER_FORMAT.md), and [REALMAP.md](REALMAP.md) shows how to start a new campaign map from real-world data. The build tools (`tools/`) live in the apps repo named in [`../links.json`](../links.json) ("apps"), CC BY 4.0; the site workflow copies them in, and to build locally you copy its `modules/tools/` here (git-ignored). How creators, referees and players use modules, and how modules are versioned, depend on each other and get trusted, is in [WORKFLOWS.md](WORKFLOWS.md). Ideas still under discussion are in [PROPOSALS.md](PROPOSALS.md). Hexmarch Scribe's campaign view and its update checker are drafted in [SCRIBE.md](SCRIBE.md).

To build locally, see section 8 of the format. The build fetches SRTM terrain tiles into `modules/.cache/` the first time it runs.

Everything in `modules/` is CC BY 4.0: fork it, change it and republish it, crediting Heph (Bakagaijin Productions). The one exception is the map icons in `assets/tiles/`: [Hex Tiles: Fantasy](https://cmartins.itch.io/hex-tiles-fantasy) by cmartins, CC BY-SA 4.0. Credit them wherever the maps go.

**Build cache.** `tools/build.py` caches the map steps in three stages under `modules/.cache/build/<module id>/`, each reused while its own inputs are unchanged (Heph 2026-11-09: redraw only what changed). The **region** stage (`hexmap.py` and the print pages) is keyed on what build.py hands those tools, the `module.json` fields they read, the admin file, `modules/geo`, `modules/assets`, `requirements.txt` and their code. The **convert** stage (`atlas_convert.py`, the Atlas Marches) adds the rest of `module.json` and the module's `atlas/` folder. The **cut** (`atlas_cache.py`, the tiles the Atlas loads) keeps a state folder between builds and cuts again only the Marches whose PNG changed, plus the League tiles they share with their neighbours. Tool code counts by what it does: a Python tool is hashed as its syntax tree without docstrings, so comments never redraw, and build.py itself is in no key. Version bumps, credits, languages, dependencies, encounters, bestiaries and encounter maps never redraw. CI keeps `modules/.cache` between runs. `BUILD_CACHE=0` turns the cache off.
