# Hexmarch Atlas map format (draft, Atlas 0.6.0)

How the Hexmarch Atlas stores a region so the browser can draw any hex at any zoom on demand.
Designed with Heph on 2026-11-05. Status: **draft**. The converter (`tools/atlas_convert.py`, Atlas 0.2.2) writes this format from today's maps on every build, into `atlas/` next to the viewer; the browser renderer (`tools/atlas.html`, Atlas 0.2.3) draws it; since Atlas 0.3.0 it is one app at `<site>/atlas/` that loads any module listed in the site's `mm.json` (`?module=<id>`), and each module's `atlas/index.html` forwards there. Rule (Heph 2026-11-05): a click always zooms in one level, centred on the hex clicked; at the 100-ft level (Furlong, since Atlas 0.4.8) only a point of interest zooms further (to an Encounter map, ENCOUNTER_FORMAT.md). Until the 0.8.x private alpha the only users are Heph and Claude, so this format changes without compatibility shims: old files are rebuilt, not migrated (Heph 2026-11-09). The `e9-`/`mm` names in it become `hexmarch-` names in 0.6.x (WORKFLOWS.md "Protocol names"). The build tools still read `module.json` (see MODULE_FORMAT.md).

A map is one JSON file plus one 8-bit indexed PNG per March. You paint terrain in any image editor; everything else is in the JSON.

## Units and zoom levels

The mile is exactly 5000 ft. Every hex is flat-topped and is measured flat to flat.

| Level | Hex size | 100-ft hexes across |
|---|---|---|
| Region | a collection of Marches | |
| March | 24 miles | 1200 |
| League | 3 miles | 150 |
| Field | 1/2 mile | 25 |
| Furlong | 500 ft | 5 |
| 100-ft hex | 100 ft | 1 |
| Encounter | 5-ft squares, keyed to a point of interest (ENCOUNTER_FORMAT.md) | |

## Map scales per module (draft, Heph 2026-11-05 and 2026-11-07)

A module sets two numbers and then lists its zoom levels, so a ruleset can use its own scales. The defaults reproduce today's Atlas exactly, so a module that says nothing gets them. Everything else in this file is written for the defaults; with other values, read "100 ft" as `unit_ft` and "5000 ft" as `mile_ft`.

- **`unit_ft`** is the bottom hex, flat to flat, and it is the lattice (default 100).
- **`mile_ft`** is this world's mile (default 5000), used only to read levels written in miles.
- **`levels`** lists the hex levels, coarse to fine. Write each size as `"hex": "24 mi"` (or `"660 ft"`), or as `hex_ft`. Every size must be a whole multiple of `unit_ft`, and the tools reject it if not. The last hex level is the bottom one and is exactly `unit_ft`.

One of the most common setups (Heph 2026-11-07), a 5280-ft mile and a 60-ft bottom hex:

```json
"scales": {
  "unit_ft": 60, "mile_ft": 5280,
  "levels": [
    {"id": "region", "name": "24 mile", "hex": "24 mi"},
    {"id": "hex6",   "name": "6 mile",  "hex": "6 mi"},
    {"id": "mile",   "name": "1 mile",  "hex": "1 mi"},
    {"id": "furlong", "name": "660 ft", "hex": "660 ft"},
    {"id": "bottom", "name": "60 ft",   "hex": "60 ft"}
  ]
}
```

Those are 2112, 528, 88, 11 and 1 bottom hexes across. The default ladder is the table in "Units and zoom levels", with ids `march`, `league`, `field`, `furlong`, `hex` and an Encounter level of 5-ft squares.

- **Centres and ownership.** A level with `n = hex_ft / unit_ft` has hex (i, j) centred on lattice hex `C = n i`, `R = n j + floor(n / 2) (i mod 2)`, for any whole n, odd or even. Ownership is by nearest centre with the usual tie rule, worked out separately for each level. Levels need not nest exactly (as today, a League can straddle two Marches).
- **Encounter levels** (`kind: "encounter"`, with `cell_ft`) are finer than the lattice and keyed to a point of interest, as in ENCOUNTER_FORMAT.md. They are optional.
- **Terrain is computed from the bottom up.** Every level except the stored ones is the most common terrain among the lattice hexes under it. The tools compute each module's ladder once, when the map is built or the module installed, and cache it with the tile cache. The renderer does not compute coarse levels while you zoom.
- **Ladders are ruleset data.** A ruleset ships default ladders (`mm`, `acks`, ...) and a module names one with `ladder`, optionally overriding values. Everything is a module, so a ladder lives with the ruleset's other data.
- **Zoom and events.** Zoom goes one level at a time down the module's ladder; the click rule is unchanged. EVENTS_FORMAT.md's `lod` takes a level `id` from the ladder.
- **No real-world step needed.** Most modules will be fantasy worlds. The real-terrain converter and the Dymaxion projection are for modules set on the real Earth. A fantasy module sets `"projection": "flat"` in `origin`: one flat plane, x east and y south in feet from the origin, no centroid. Its terrain is hand-painted or generated by any tool that writes the PNGs.
- **Paint where you like (proposal).** `scales.paint` may name any level `id`. The author paints at that level, and finer levels get seeded procedural detail from it, as the converter does now from the League pages. Hand overrides still apply. Nobody should have to paint 2112 pixels across a 24-mile hex.
- **Lattices need not match between modules (proposal).** Two modules on the same region with different `unit_ft` have hexes that do not line up. Porting terrain from one to the other is a resample (nearest centre), done by a tool; a real-terrain module is instead rebuilt from its source data. Addresses are per module: `#world:CCRR:CCRR` means the level named by `scales.address_level` (default `league`) and then the bottom hex inside it.

- **Storage: one picture per hex of a chosen level (Heph 2026-11-07).** `scales.tile` names a level `id`, and the module has one terrain PNG per hex of that level, each with one pixel per bottom hex. The default ladder's tile level is `march` (the 1600 x 1200 pictures below). For a level of `n` bottom hexes the picture is about `4n/3` wide and `n` tall, as 1600 x 1200 shows for n = 1200. So with a 60-ft bottom hex and a 6-mile tile level (`"tile": "hex6"`, Heph 2026-11-07), each picture is about 704 x 528 pixels, and a 24-mile hex is 16 of them. The tile level can be any level, so a module picks whatever size suits it; the picture size is never fixed by the format.
- **Summaries in the pictures' dead corners** belong to the default ladder. Other ladders use computed summaries, as above.

- **Print pages follow the module's ladder (Heph 2026-11-07).** The atlas PDF is cut by the module's own levels, not the default ones. For the 24 / 6 / 1 mile / 660 ft / 60 ft setup that means pages such as one 6-mile hex showing its 1-mile hexes.

## Fantasy worlds: one painted level (Atlas 0.5.14)

The first working form of the ladder above, built for Mystara (Heph 2026-11-08). It is a **flat** world: one plane, no projection, no real terrain behind it. Only one level is painted, and the Atlas works out the rest.

**The module folder** holds `module.json` and one picture:

- `scales`: `unit_ft`, `mile_ft` and **five** levels, coarse to fine, each with an `id`, a `name` ("8 mile") and a `hex` size ("8 mi", "660 ft"). The last level is the bottom hex, exactly `unit_ft`. `paint` names the level that is painted; for now it must be the second one. Mystara: 64 mi, 8 mi, 1 mi, 660 ft and 60 ft on a 5280-ft mile, painted at 8 mi (5632, 704, 88, 11 and 1 bottom hexes across).
- `atlas.projection`: `"flat"`. `atlas.paint` names the picture. `atlas.terrain` lists the terrain types: `id`, `name`, `colors` (every colour in the picture that means this terrain), `tile`, `icon` and `travel` (time multiplier, `null` for no travel on foot). `atlas.travel` may set the pace and road multipliers as for real-terrain modules.
- `places`: `id`, `name`, `kind`, `icon`, `rank`, and `hex` as `"<col>.<row>"` of the painted level. An optional `at: [dC, dR]` moves the place off the hex centre by that many bottom hexes.

**The picture** has one pixel per painted hex. Pixel (x, y) is column x, row y, with odd columns half a hex lower, the same layout as the lattice. Black (`#000000`) is off the map. Every other colour must be listed under exactly one terrain; the tool stops on any it can't place.

**Levels the Atlas works out.** The level above the painted one takes the most common terrain among the painted hexes it owns (nearest centre, as everywhere). Each finer hex takes the terrain of the painted hex under its centre, moved by seeded noise of up to about half a painted hex, so borders wander and coasts look natural. The noise is keyed to the lattice, so a hex looks the same every time and on every device. Nothing finer than the painted level is stored. Hand-painted detail at finer levels is for later.

**Addresses** are plain numbers, because a painted hex can hold hundreds of bottom hexes across and the two-character labels below stop at 329:

| Address | Opens |
|---|---|
| `#world:<col>.<row>` | a painted hex, by the painter's own grid (0-based) |
| `#world:<col>.<row>:<C>.<R>` | a bottom hex, by its lattice column and row (the painted hex is for reading) |
| `#field:<col>.<row>:<C>.<R>` | the hex one level below the painted one that holds that bottom hex |
| `#march:<i>.<j>` | a hex of the level above |

`#site:<id>` works as for any module. The campaign state file and character knowledge take these addresses as they are (`world:87.102:61248.72160`).

**Map files.** `atlas_flat.py` (apps repo, `modules/tools/`) builds the folder into one self-contained file, `<id>.e9atlas.json`:

```json
{ "format": "e9-atlas-file", "version": 1,
  "module": { "id", "title", "version", "credits", ... },
  "map": { "flat": true, "scales": { "levels": [{ "id", "name", "n" }] }, "terrain", "paint": { "w", "h", "data": "<base64, one byte per hex>" }, "pois", ... },
  "tiles": { "<name>": "data:image/png;base64,..." } }
```

The Atlas opens it with **Modules › Open a map file…**. It is kept in that browser only (IndexedDB), listed as "on this device" with a Remove button, and never uploaded. That is how private modules (Mystara, ACKS) are played without a public repo. A public flat module can be built into its module folder the same way later.

## Fog of war (Atlas 0.5.17, Heph 2026-11-09)

Each hex of the League (painted) level is in one of six states for the creature whose map it is:

| State | Look |
|---|---|
| in sight + explored | full colour, thin gold rim |
| in sight + visited | full colour |
| explored | sepia |
| visited | faded sepia |
| rumoured | blank parchment with a dotted outline; rumoured places show as a faded icon with "Name ?" |
| unknown | blank parchment |

**Visited** means seen or passed through: seeing a hex visits it. **Explored** means searched thoroughly, which reveals hidden sites. Visiting a hex replaces any rumour of it.

**Storage.** What one creature knows is stored on that creature as dated `knowledge` entries (CREATURES_FORMAT, Companion CHARACTER_FORMAT), never per 100-ft hex. A fog entry names the League by its centre address in `hex`, with `"how": "seen"`. Entries can also carry `"explored": true` or `"rumour": true`. Common knowledge stays in the state file's `revealed`.

**Travel.** When the party travels, every hex within sight of any point on the route is visited, for **each character** in the party. When the Atlas runs inside the Companion, it sends `{type: "e9-atlas", event: "knowledge", module, ids, add, remove}` and the Companion saves the entries to those sheets. On its own, the Atlas writes the sheets in the browser.

**Sight range is a procedure.** The Atlas asks for procedure `sight-range` in the ruleset's or module's procedures.json. That procedure takes the terrain (and later light and height) and returns miles. Until the Atlas can run procedures, it uses a stand-in table: grass and clear 3, light woods 1.5, heavy forest 0.5, hills 6, mountains 12, bog 2, sea 6, desert 4.

**Views.** The referee view has no fog. The Party box has a **Preview fog** toggle and a brush that marks hexes as visited, explored or rumoured, or hides them, for the party. Character mode (Party › Show the map as) always shows that creature's fog.

**Later.** A "charted" state, where a map reveals coarse terrain only.

## The lattice

The whole region shares one grid of 100-ft hexes, with flat tops and **odd columns shifted down half a hex**. A hex's global address is `(C, R)`, and its centre in feet is

    x = C * 86.6025   (100 * sqrt(3) / 2)
    y = (R + 0.5 * (C mod 2)) * 100

with x running east and y running south from the map's `origin` (see the JSON). Because the mile is 5000 ft, every larger hex centre falls exactly on a lattice hex:

| Level | Hex (i, j) has its centre at lattice hex |
|---|---|
| March | C = 1200 i, R = 1200 j + 600 (i mod 2) |
| League | C = 150 i, R = 150 j + 75 (i mod 2) |
| Field | C = 25 i, R = 25 j + 12 (i mod 2) |
| Furlong | C = 5 i, R = 5 j + 2 (i mod 2) |

**Furlong** (Heph 2026-11-06, Atlas 0.4.8): a 500-ft hex, named for the old furlong (660 ft), which is close enough on a 5000-ft mile. A Field is 5 Furlongs across and a Furlong is 5 lattice hexes across, so the level needs no new data. It has no stored summary: the Atlas works out its terrain as the most common terrain among its 100-ft hexes, by the rule in "Map scales per module", and caches it. In the viewer, Field shows Furlongs, the Furlong level shows 100-ft hexes, and places open their Encounter maps at the Furlong level.

**Tile cache** (Heph 2026-11-06, Atlas 0.4.9): a build product, not part of the format. The browser never loads the March PNGs. `tools/atlas_cache.py` cuts them into small pieces under `atlas/cache/` and adds a `cache` block to map.json that says where each piece is and how big it is. Every pixel in a piece is a terrain index (0 means nothing), and a tile holds only the hexes its March or League owns.
- `overview.png` has one pixel per League over the whole region. It draws the Region and March views and should stay under about 100k Leagues; the build warns past that.
- `f/<march>.png` holds a March's Field summaries. The League view loads the ones within 5 Marches of the view's centre (91 at most).
- `u/<i>_<j>.png` holds a League's Furlongs. The Field view loads the ones within 4 Leagues (61 at most).
- `h/<i>_<j>.png` holds a League's 100-ft hexes. The Furlong view loads the ones within 3 Leagues (37 at most).

As the view moves, tiles load around it. Tiles of that kind that fall outside the ring are dropped unless they are on screen, so there is no hard edge and no scroll limit. The cache is rebuilt whenever a March PNG changes: `cache/sources.json` keeps the PNGs' hashes. The March PNGs stay the source of truth.

A lattice hex belongs to the March, League or Field whose centre is nearest. On an exact tie, the **higher** i wins, then the higher j. With that rule every March owns columns Cm − 800 to Cm + 799 and rows Rm − 600 to Rm + 599, so its hexes fit its PNG exactly, and every March holds exactly 64 Leagues and 2304 Fields (by their centres), all of which fit the summary blocks below (checked by the converter on 2026-11-05; the first draft said "lower", which left one row of each March's hexes outside every PNG).

## Terrain PNGs: one per March

Each March is a **1600 × 1200** 8-bit indexed PNG. Pixel (x, y) is lattice hex

    C = Cm - 800 + x,   R = Rm - 600 + y

where (Cm, Rm) is the March's centre hex. Pixel columns keep the global odd/even parity, so odd pixel columns sit half a hex lower. In an ordinary image editor the map therefore looks about 15% too wide and slightly staggered. The Atlas editor will show it true to shape.

Neighbouring March PNGs overlap at the corners. Only pixels that belong to this March (nearest-centre rule) are read. The four corners outside the March hexagon are each about 400 × 600 pixels of dead space, and they hold the summaries:

| Pixels | Holds |
|---|---|
| (0, 0) | the March's own terrain |
| x 2–12, y 2–10 (11 × 9), upper left | one pixel per League. Block pixel (u, v) is League i = iL − 5 + u, j = jL − 4 + v, where (iL, jL) is the League under the March centre |
| x 1533–1597, y 1149–1197 (65 × 49), lower right | one pixel per Field. Block pixel (u, v) is Field i = iF − 32 + u, j = jF − 24 + v, where (iF, jF) is the Field under the March centre |

A block pixel for a League or Field whose centre belongs to a neighbouring March is left as colour 0 ("none"). The converter gives each 100-ft hex seeded detail on top of the source maps: borders between parent hexes wander up to 900 ft, and each terrain becomes a natural mix (glades in forest, copses in grassland), repeatable because the noise is keyed to the global lattice. The tools fill each summary with the **most common** terrain among all its member hexes (a League or Field can straddle two Marches), never a colour average, and colour 0 never wins while any terrain is present. A painter may then edit a summary by hand, and the renderer uses each level's own summary. That lets you paint a coarse map first and refine it later.

### Palette

Terrain is matched by **colour**, not by palette index, because some editors reorder palettes when they save. Colour 0 (`#000000`) means none or outside. Up to 255 other colours can each name a terrain type in the JSON.

## Projection: Dymaxion, one face per region

Decided by Heph on 2026-11-05: the Atlas uses **Buckminster Fuller's Dymaxion projection** (the icosahedral layout, using Robert W. Gray's published transform), so one scheme covers every setting from Leinster to Francia to Barsoom. Two rules:

1. **Each major region gets its own centroid.** The icosahedron is turned so that one face's centre (where the triangle touches the planet) sits on the region's centroid, with true north pointing up the page there. That whole region then lives on one flat face with one 100-ft lattice.
2. **Seams always fall in the middle of the ocean.** A face reaches about 21° of arc (about 2,300 km) from its centre before the nearest edge, so a region the size of Ireland never touches a seam. Separate regions (Britain, Francia) get their own centroids and faces, and maps join them across water.

For Ireland the centroid is the **Hill of Uisneach**, Westmeath (53.489° N, 7.561° W), the traditional centre of the island. Every Irish coast lies within 2.5° of it. Measured with the converter's transform (tools/dymaxion.py), the local scale error is under 0.1% around Dublin, under 0.5% anywhere in Leinster and under 0.8% at the island's far tips (Malin Head, Mizen Head), and distances from Uisneach are true to within 0.4%. Equirectangular, by contrast, reaches 2.4% across Leinster alone. One face vertex points due north.

`origin` names the centroid and gives the position of lattice hex (0, 0) in feet on that face. The scale is set so that distances at the centroid are true (mean Earth radius 6,371,008.8 m).

`labels` gives the March and League lattice (i, j) that are labelled `00`/`0000`: the top-left March and League of the region's fixed extent (module.json `atlas.extent`, for Ireland the whole island), so labels never shift when a map grows. March PNGs are named by their label, e.g. `terrain/0807.png`.

## The map JSON

Sections appear in this order: base terrain, then rivers and roads, then region names, then points of interest.

```json
{
  "format": "e9-atlas/1",
  "id": "isle-of-mists",
  "title": "Beyond the Pale: The Isle of Mists, 1422",
  "names": {"An Life": {"en": "Liffey"}},
  "origin": {"projection": "dymaxion", "centroid": {"name": "Uisneach", "lat": 53.489, "lon": -7.561}, "x_ft": 0, "y_ft": 0},
  "labels": {"march": [-7, -7], "league": [-55, -49]},

  "terrain": {
    "types": [
      {"color": "#7fae4e", "id": "grass", "name": "Grassland", "tile": "bg-green", "travel": 1},
      {"color": "#2e6b2e", "id": "forest", "name": "Forest", "tile": "bg-green", "icon": "forest", "travel": 2},
      {"color": "#6e6a5a", "id": "bog", "name": "Bog", "tile": "bg-grey", "icon": "swamp", "travel": 2},
      {"color": "#4f86a8", "id": "sea", "name": "Sea", "tile": "bg-blue", "travel": null}
    ],
    "marches": [{"id": "0708", "i": 0, "j": 1, "png": "terrain/0708.png"}],
    "overrides": {"0302:1506": "forest"}
  },

  "rivers": [{"name": "An Life", "class": 3, "points": [[41250, 88010], [41320, 88400]]}],
  "roads": [{"name": "Slí Chualann", "class": "roman", "points": [[50100, 60200], [50900, 61000]]}],
  "crossings": [{"hex": [640, 512], "kind": "ford"}],

  "regions": [{"name": "Cill Dara", "kind": "county", "label": [62000, 140000], "outline": [[0, 0]]}],

  "pois": [{"id": "ceanannas-mor", "name": "Ceanannas Mór", "kind": "abbey", "icon": "church", "hex": [812, 410], "book": "B2"}]
}
```

- **Points are in feet** from `origin`: `[x east, y south]`. Rivers and roads are polylines that the renderer smooths, so their points need no splines. A river's `class` sets its drawn width.
- **Roads** come in three classes (Heph 2026-11-05): `roman` (a size class named for familiarity, not history: any great paved or engineered highway; in Ireland, the five ancient slighe from Tara), `local` and `trail`. A module lists them in module.json `atlas.roads` (Atlas 0.4.18):
  ```json
  "roads": [{"name": "Slí Mhór", "class": "roman", "via": ["Baile Átha Cliath", "Baile Átha Luain", [53.27, -9.05]]}]
  ```
  A via point is any site name in the module or a `[lat, lon]` point; an unknown site, class or point fails the build. `tools/atlas_roads.py` (run by build.py after the tile cache) lays each leg between via points along the cheapest way on foot over the Field (half-mile) terrain, using the map's travel multipliers: no leg crosses sea or a lake, and grass wins over bog and mountain. It then straightens the path wherever a straight line stays within 600 ft of it on passable ground, gives it a seeded sway (a gentle wander of up to about 150 ft on a roman road, 200 ft on a local road and 260 ft on a trail, pinned at the via points and never onto ground with no way on foot; Heph 2026-11-07), and writes each road to map.json as a polyline in feet. Where a road meets a river it writes a crossing: a `bridge` on a `roman` road, a `ford` on the others, or what the road's optional `"crossing": "bridge" | "ford"` says. A crossing carries its 100-ft `hex`, the exact point `at` (feet), the road's heading `angle` (degrees) and the `span` it needs (feet, from the river's width), plus the `road` and `river` names. The Atlas draws roman and local roads from the Region view and trails from the League view down, at true width (30, 15 and 6 ft) once zoomed in, and crossings from the League view down. Plain marks stand in for the bridge and ford icons Heph is drawing. The Route tool counts a sample as on a road when it is within about a third of a hex of one, and the road's multiplier replaces the terrain's there (so a bridge carries the route over a river). Hovering over a road names it.
- **POI positions** (Heph 2026-11-06) are a whole lattice hex `"hex": [C, R]`: a PoI is always one 100-ft hex, with no offset inside it. The hex gives every level its address for free (which Field, League and March the place is in). At the 100-ft (Furlong) level a PoI draws centred in its hex and never past the hex's edge; its icon and label shrink to fit, and the label is left off when it would be too small to read. Visibility at the other levels is still to be worked out (open question). Older files with an `"ft"` offset still load; the offset is ignored.
- **Travel** (Heph 2026-11-06, Atlas 0.4.11) prepares the path tool (plot a route, estimate the time), which will later hand off to the travel procedures (EVENTS_FORMAT.md). Each terrain type's `travel` is a time multiplier against the module's pace: `1` is normal pace, `2` takes twice as long, and `null` means no travel on foot (sea, lake: boats come later). The top-level `travel` block gives the pace and the road multipliers. On a road the road's multiplier replaces the terrain's:
  ```json
  "travel": {"pace": {"mi_per_hour": 3, "hours_per_day": 8}, "roads": {"roman": 0.5, "local": 0.75, "trail": 1}}
  ```
  A module sets its own values in module.json `atlas.travel`, with the same shape plus `terrain`: `{"forest": 2, "woods": 2, "bog": 3}`. Anything it leaves out keeps the tool's defaults (3 mi/h, 8 h a day; roman 0.5, local 0.75, trail 1; terrain as in atlas_convert.py). A ruleset's procedures may later set the party's own pace, for example from encumbrance; the multipliers stay with the map. The Atlas key shows each terrain's multiplier and walking speed, and `E9Atlas.travel(legs)` adds up a route: legs are `[{mi, terrain, road?}]`, and it returns `{hours, days, mi}`.
  The **Route** button (Atlas 0.4.12) is the first path tool. While it is on, a click adds a stop at the centre of the hex under it instead of zooming in, and dragging still pans. The route is measured on the terrain of the level being drawn (Leagues, Fields, Furlongs or 100-ft hexes), sampled every quarter hex along each straight leg. A leg that crosses terrain with no travel on foot is flagged. Roads count once the map has them.
- **Party marker** (Heph 2026-11-07, Atlas 0.4.17) shows where the party stands. It is always one 100-ft hex, written as a hex address without the `#` (`world:CCRR:CCRR`), and it is drawn as a red pennant at every zoom, with its 100-ft hex shaded once that hex is big enough to see. The **Party** button places it (a click puts it on the centre 100-ft hex of the hex clicked at that level), moves it, removes it, or jumps to it. A route starts at the party, and **Move party here** in the Route box puts the party at the route's last stop and adds the route's time to the party's running travel time (Reset time sets it back to zero). The position and time live in the campaign state file (STATE_FORMAT.md, since Atlas 0.5.11; before that they were kept per module in the browser under `e9-atlas-party:<module id>`, which the Atlas still picks up once). The Party box also shows the campaign clock, the session, and how many places and hexes the party has found, and the key marks found places with ✓. An embedding app sends the whole file as `{"type": "e9-atlas", "state": {...}}`. An app that embeds the Atlas may set the party by posting `{"type": "e9-atlas", "party": {"hex": "world:CCRR:CCRR", "hours": 0} | null}`, and each move made in the Atlas is posted to the parent as `{"type": "e9-atlas", "event": "party", "module", "hex", "hours"}`. An old-grid hex posted as the party (`legacy:world:CCRR`, or any old key with the `legacy:` prefix) is placed at the centre of its new League and echoed back as a party event with the new address, which is how the Companion converts saved positions. The Atlas also posts `{"type": "e9-atlas", "event": "view", "module", "hash"}` whenever the view changes, and takes `{"type": "e9-atlas", "show": "#…"}` to move the view. Later, moving the party is what queues place and terrain triggers (EVENTS_FORMAT.md section 8); the campaign, not the browser, will then hold the position. Parties will want their own pennants (Heph 2026-11-07): the marker is expected to grow optional per-party `icon` (a tile name) and `colour`, and a list of parties, without changing the single-party message above.
- **Place ranks** (Heph 2026-11-06, Atlas 0.4.16) thin out place icons when zoomed out. Each PoI has a `rank`: `1` (major) shows from the Region view, `2` (notable) from the March view, and `3` (minor) from the League view down. A module sets ranks in module.json `site_ranks: {site name: 1 | 2 | 3}`. Without one, towns are 1, abbeys 2 and everything else 3. Among the places a level shows, the most important are drawn first, and a place whose icon or name would overlap one already drawn waits for a closer zoom. This is the first rule of PoI visibility; player visibility comes with the referee and player views.
- **PoI hierarchies** (Heph 2026-11-07, Atlas 0.5.1). A place can hold sub-places: a cave system with several mouths, a city of several hexes with several gates. Each sub-place is an ordinary PoI in its own 100-ft hex and names the one PoI it collapses into: `"parent": "<id>"` in map.json, from module.json `site_parents: {sub-place name: parent name}`. Nesting can go any depth (a city, its quarters, their gates); a loop or an unknown name fails the build, and a sub-place whose parent is off the map stands on its own.
  - On the map, the top place's rank decides when the whole tree first shows. A place with sub-places is drawn as itself while any two of its sub-places would crowd each other on screen (closer than two icons, so their names fit too), and as its sub-places once they are all that far apart; at Furlong level it is always its sub-places, since each fills its own hex. The parent is a summary: anything the party should be able to walk into at close zoom (the market square as well as the gates) is a sub-place of its own.
  - In the key, in every view, the Places list is the places drawn in view. One with sub-places has ▶ in front of it; clicking ▶ turns it to ▼ and lists its sub-places under it, indented, each with its own ▶ if it has sub-places in turn. Clicking a name still zooms to that place.
  - Later: the Route tool and party marker arriving at the nearest sub-place (gate) of a collapsed place, a parent's footprint (its hexes or anchored map) shaded on the Field view, and in the player view showing only the sub-places the party has found.
- **`names`** holds the Language box's translations, keyed by the name as drawn, as in module.json today.
- **`overrides`** fixes a single hex at any level without repainting (`<march>:<league>`, and later deeper addresses).
- An optional **elevation PNG** per March, 16-bit greyscale with the same geometry, can come later for hill shading.

## Hex addresses

Decided by Heph on 2026-11-05: **`#world:CCRR:CCRR`**. The first `CCRR` is the League (3-mile hex), and the second is the 100-ft hex inside that League. `#world:CCRR` alone means the whole League. A full address opens the Furlong level with that 100-ft hex picked. **`#field:CCRR:CCRR`** (Atlas 0.4.8) opens the Field that holds the 100-ft hex; the tools write it with the Field's centre hex.

**Labels.** Each column or row label is exactly two characters: `00`–`99`, then `A0`–`A9`, `B0`–`B9` and so on. The letters `I`, `O` and `Q` are never used, so 23 letters give 330 values (0–329). For example, 100 = `A0`, 147 = `E7`, 200 = `L0`.

| Part | Counts | Range used |
|---|---|---|
| League column, row | League lattice (i, j), shifted so the region's top-left League is `0000` | Ireland needs about 70 columns × 100 rows |
| 100-ft hex in the League | lattice hexes from the League's bounding box: column 0 = League centre C − 100, row 0 = centre R − 75 | columns `00`–`K9` (0–199), rows `00`–`E9` (0–149), 22,500 hexes per League; the centre hex is column `A0`, row `75` → `A075` |

Parity carries through: column 0 is an even global column, so odd columns sit half a hex lower, as everywhere else. With the tie rule above every League owns exactly columns 0–199 and rows 0–149 of its box (checked with a script). Tools write the canonical form (upper case, with the hex inside the League that owns it), and the viewer reads either case. Furlong, Field and March are derived from the address; `#field:` only says which level to show.

**Old links** (Atlas 0.5.6) were removed in Atlas 0.6.0: the Atlas no longer reads the old module viewer's `#l-…`, `#march-N`, `#atlas-N`, `#p-<site>` or `#legacy:…` links. map.json may still carry a `legacy` table until `atlas_convert.py` next changes; the Atlas ignores it.

**Places by id** (Atlas 0.5.7). `#site:<slug>` opens a place's 100-ft hex, where `<slug>` is its map.json PoI `id` (the site slug). The module page's "Show on the map" links use it.
